<objective>
Add per-invoke correlation-id capture and extend the structured audit line so every invoke — unified or legacy — records `code3rd, endpointId, latency, outcome, requestId` (PIPE-03). The id flows through MDC for engine-layer log inheritance and is passed explicitly into the audit event so attribution is independent of the streaming callback thread.

Purpose: There is no MDC usage anywhere in the codebase today; correlation id is the first cross-line traceability mechanism and the foundation for the Phase 5 log viewer. This slice is API-layer only and runs in parallel with 03-01 (no shared files).
Output: Extended `InvokeAuditEvent`/`InvokeAuditLogger`, an `IntegrationInvokeProperties.mappingEnabled` binding, correlation-id + MDC + outcome classification in `IntegrationInvokeService`, and two new unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (via upstream gateway) -> IntegrationInvokeService | Inbound `X-Request-Id`/`X-Trace-Id` headers are untrusted attacker-controllable input. |
| invoke pipeline -> log sinks (audit + app log) | The correlation id and outcome are written to logs; unsanitized input could forge log lines. |
| per-request virtual thread -> MDC ThreadLocal | MDC state must not leak across requests when carrier/platform threads are reused. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering / Repudiation | inbound `X-Request-Id` -> MDC / log line | mitigate | `sanitizeCorrelationId` strips `\r`/`\n` and caps length (~128) before `MDC.put`; id is MDC-only, never echoed to the vendor (D-12). `IntegrationInvokeServiceTest` asserts CRLF stripping. |
| T-03-04 | Repudiation | MDC `requestId` ThreadLocal under virtual threads | mitigate | D-11: `MDC.put` in `try`, `MDC.remove` in `finally` on both invoke + stream; correlation id ALSO passed explicitly into `InvokeAuditEvent` so audit attribution is independent of thread reuse / callback thread (A1/Q2). |
| T-03-02 | Information Disclosure | audit log line + outcome classification | mitigate | Audit logs metadata only (code3rd/endpointId/method/path/status/latency/requestId/outcome); never `body`/`credentials`/`keyRef`. SLF4J `LoggerFactory`, not Lombok. |
| T-03-06 | Information Disclosure | pipeline-error outcome path | mitigate | D-19/D-20: typed exception caught to set `PIPELINE_ERROR(<stage>)`, then rethrown to `RuntimeApiExceptionHandler` -> structured `{code,message,details}`; no stack trace to caller; `vendorHttpStatus=0` distinguishes from vendor errors. |
</threat_model>
